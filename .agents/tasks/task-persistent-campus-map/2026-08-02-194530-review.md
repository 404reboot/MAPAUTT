# Persistent interactive campus map with GLB-authoritative inventory

This change replaces a bare Spring Boot scaffold with a complete MariaDB-backed campus map system. A shared `MapLocation` identity table holds the dual-identifier design (stable slug `mapKey` + exact GLB scene-root `glbObjectName`), with `@MapsId` composition linking `Instalacion` and `AreaVerde` detail tables. A JSON registry file serves as the source-of-truth bridge between the GLB model and the database, validated at startup with environment-sensitive behavior (warn in dev, fail in prod). The REST API is read-only; the admin panel is edit-only (no create/delete). The Three.js frontend binds the registry inventory to GLB scene objects and renders detail cards using safe DOM construction.

Watch for: the admin panel has no authentication or authorization (confirmed); `LocationDetailDto.details` is typed as `Object`, which degrades Jackson serialization predictability (confirmed); the `GlobalExceptionHandler` applies to `@RestController` only but the admin controller throws raw `IllegalArgumentException` that will surface as a generic 500 (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The admin panel exposes unrestricted POST endpoints to mutate location metadata. There is no Spring Security dependency, no authentication filter, no CSRF token enforcement beyond Thymeleaf's default behavior. Anyone who can reach `/admin-panel` can edit any location.

The inventory validator runs a full table scan plus N+1 subtype queries at startup for all 54 entries. This is acceptable at current scale but will become a cold-start bottleneck if the campus grows or the database is remote with latency.

The REST layer uses `Object` for the polymorphic detail field, which means Jackson's output structure depends on runtime type rather than a declared contract. Clients cannot predict the JSON shape from the DTO declaration alone.

The frontend loads Three.js and OrbitControls from unpkg CDN URLs pinned to a specific version, which is brittle against CDN outages and makes the app unable to function in an air-gapped or CSP-restricted deployment.

## Unprotected admin panel

The `pom.xml` adds no Spring Security starter. The `AdminPanelController` is a plain `@Controller` with `@RequestMapping("/admin-panel")` — every GET and POST is open to the network. Thymeleaf includes a CSRF token in forms by default when Security is on the classpath, but without the dependency the token is not rendered, so CSRF protection is absent entirely. This means:

```
POST /admin-panel/instalaciones/edificio-d/edit
```

can be issued by any client with network access to the application, altering display names, descriptions, and operational status of campus locations.

If the plan is to add auth later, the gap should at least be documented as a known open item, and the routes should be behind a TODO-gated profile flag or disabled in prod until secured.

## Admin exception handling gap

`AdminPanelController.editInstalacionForm` and `editAreaVerdeForm` throw `IllegalArgumentException` when a location isn't found:

```java
MapLocation location = mapLocationRepository.findByMapKey(mapKey)
        .orElseThrow(() -> new IllegalArgumentException("Location not found: " + mapKey));
```

`GlobalExceptionHandler` is annotated `@RestControllerAdvice`, which only intercepts exceptions from `@RestController` beans. The MVC controller's `IllegalArgumentException` will propagate to Spring's default error handling — a Whitelabel Error Page in dev, or a raw 500 in prod with no user-friendly message.

The fix is either to add a separate `@ControllerAdvice` targeting the `app.controller.mvc` package that renders an error template, or to change the admin controller to use `LocationNotFoundException` and handle it in a general advice.

## Polymorphic detail serialization

`LocationDetailDto` declares:

```java
public record LocationDetailDto(
        String mapKey,
        LocationType locationType,
        String displayName,
        String description,
        Object details    // <-- untyped
) {}
```

Because the compile-time type is `Object`, Jackson won't include any type discriminator, and client tooling (OpenAPI generators, TypeScript codegen) cannot infer the schema. A sealed interface or `@JsonTypeInfo` with `locationType` as the discriminator would make the contract explicit and enable forward-compatible deserialization if a third location type is added later.

## CDN-pinned frontend dependencies

```javascript
import * as THREE from 'https://unpkg.com/three@0.160.0/build/three.module.js';
import { GLTFLoader } from 'https://unpkg.com/three@0.160.0/examples/jsm/loaders/GLTFLoader.js';
import { OrbitControls } from 'https://unpkg.com/three@0.160.0/examples/jsm/controls/OrbitControls.js';
```

These imports load at page-view time with no local fallback. If unpkg is slow or blocked (university network firewalls are common), the entire map page fails silently — `initScene()` never runs because the import fails before `DOMContentLoaded`. Vendoring the modules into `/static/vendor/` or using an import map with a local fallback would make the page resilient.

## Validator startup cost

`MapInventoryValidator.validateInventory()` iterates all 54 registry entries and for each one calls `mapLocationRepository.findByMapKey()` plus either `instalacionRepository.findByMapKey()` or `areaVerdeRepository.findByMapKey()`. That's up to 108 queries during `ApplicationReadyEvent`. The data fits trivially in memory: fetch all `MapLocation` records, all `Instalacion` records, and all `AreaVerde` records in three queries, build maps keyed by `mapKey`, and validate in a loop.

## Test coverage gaps

Notably absent from the test suite:

- `AdminPanelController` — no `@WebMvcTest` exercising form submission, validation errors, or redirect behavior.
- `MapInventoryValidator` — no test that verifies the warn-vs-fail modes produce the expected outcome (log vs. exception).
- Integration test with an actual database (H2 or Testcontainers) to validate Flyway migrations run cleanly and JPA mappings are consistent with the DDL.
